# 架构、内存与异常诊断

持久文件位于 `/etc/storage/ShellCrash`；管理入口为 Padavan `/custom/AnyTLS.asp`（文件名保留兼容，界面名称为 ShellCrash）。`padavan_ui.sh` 在 RAM 中生成受原路由器认证保护的入口与控制脚本，对 `/www/state.js` 做 bind mount 加入菜单。原 SSR 页面保留，不另起 Web 后台。

前端以 Clash API 读取节点状态，控制动作通过 Padavan 原有 `nvram_dump` / 系统脚本功能执行。随机控制 token 检查请求参数，API 密钥仅通过认证入口交给当前浏览器。不将密钥放入公开 `/ui` 静态文件。该信任模型要求 Padavan HTTP 认证保护 `/custom`，并禁止公网开放后台及 API。登录会话中的浏览器用户可以管理代理；没有多用户权限隔离。

核心使用 `GOMEMLIMIT=12MiB`、`GOGC=25` 减少 Go 堆扩张。这不是整个进程的硬限制；二进制 tmpfs 映射、RSS、连接缓存和内核网络缓冲都会消耗物理 RAM。程序约 28.8 MB，压缩包约 9 MB；启动阶段需同时容纳下载与解压文件。45 MB 的 tmpfs 容量限制不等于预占 45 MB RAM。

没有新增常驻监控程序。现有每分钟 cron 调用选择保存脚本，顺带采样可用内存、RSS、共享页、Slab、TCP/UDP 缓冲和连接跟踪。趋势以 uptime 截取 24 小时并限制 1441 行，重启清空 RAM 数据。

可用内存低于 16 MiB 发出提示；低于 12 MiB 暂缓测速、订阅、规则、DNS 与内核更新。清理只针对可重建的压缩程序缓存、确认未被引用的旧 GFW 运行文件和过大的运行日志。日志超过 64 KiB 时保留最后 32 KiB，异常记录与诊断证据不删除。清理与订阅、内核更新共用操作锁；启动期间不清理。不定时 drop_caches、不杀掉连接，也不因阈值触发反复重启。并不能保证自动恢复所有低内存场景。

守护只在内核确实退出时恢复：记录事件时间、近期资源采样和系统 OOM 证据；重试以 1～5 分钟退避，同一次故障不重复增加异常数。事件最多 100 条、证据最多 8 份，均在 `/tmp/sc-admin`，重启会丢失。页面异常次数为本次启动期间累计，不是 24 小时滚动计数；内存趋势才是滚动窗口。

没有 OOM 或明确错误证据时显示原因未确定，不能把所有退出都当成内存不足。需要长期留存时应把诊断文件定期复制到自己的服务器。公开项目不内置云服务器账户或自动上传凭证。

Storage 保存通过 tar 流与 bzip2 小块压缩，压缩后必须在 512 KiB 内才写入 Flash；失败不允许声称已固化。配置大小、其他插件文件及 Flash 容量仍需要使用者核实。

## 运行监控页

“监控”集中展示 MemAvailable、代理 RSS、保护状态、连接跟踪、趋势与异常。页面可手动刷新或清理临时文件；前后台读数均使用可用内存。原每分钟采样任务负责自动清理，不增加驻留进程。浏览器每 30 秒读取状态，仅在监控页展开趋势时读取历史；隐藏页面停止周期查询。历史接口只传绘图所需字段。

清理结果区分文件减少量和可用内存前后读数：后者会随业务变化，不能作为精确释放量。没有可清理文件时明确提示，不停止代理、不清空系统缓存、不写 Storage。RSS 包含映射程序页等，GOMEMLIMIT 是 Go 管理内存目标而非整个进程的硬上限；持续增长需要结合连接数和异常证据分析。
